# 旅行足迹正式落地实施计划

## 1. 目标与边界

在保留 React、TypeScript、Vite、Express 以及现有 PC/手机端 UI 的前提下，将当前 Demo 的 JSON 存储、模拟身份、模拟地图和不完整图片上传逐步替换为本地可正式使用的能力。

明确不做：重新设计 UI、更换前端技术栈、AI、社区、支付、腾讯云或其他部署工作。正式备份与恢复暂缓；当前不安全的备份入口需要在正式使用前停用。

推荐顺序：

1. 修复生产构建与本地启动。
2. SQLite、迁移和旧数据导入。
3. 登录、Session 和权限。
4. 高德地图、POI 和路线。
5. 图片上传、压缩、EXIF 和缩略图。
6. 行程稳定、架构收敛和发布验收。

总工作量预计 20–31 人日，单人约 4–7 周。

## 2. 当前审查结论

### 2.1 可以保留

- React + TypeScript + Vite 前端和 Express API 技术栈。
- PC、手机端页面结构、视觉和主要交互流程。
- 地点、访问、行程、行程日、行程项目、攻略、清单和媒体领域模型。
- 已接入 HTTP API 的主要 CRUD 流程。
- 用户实际创建的地点、行程、攻略和清单数据及现有 ID；项目内置演示业务数据不再保留。
- 已预留的 WGS84、GCJ-02、POI、EXIF 字段方向。

### 2.2 需要重构

- `server.ts`：拆分启动、配置、路由、服务、数据库访问和权限中间件。
- `src/App.tsx`：拆分会话、数据加载、页面容器和全局状态。
- `src/dbEngine.ts`：替换为 SQLite Repository/Service。
- `src/api.ts`：统一状态码、错误结构、Session 和上传协议。
- 地图组件：保留页面容器，替换固定范围模拟地图。
- 图片上传：由 Base64 JSON 改成 multipart 和服务端统一处理。
- 行程写操作：增加校验、事务、引用约束和权限。
- 收藏、想去、去过：由地点全局字段改成用户维度状态。

### 2.3 应删除或停用

- 默认 `admin123`、`travel123` 和静态 SHA256 加盐方案。
- `x-user-id` 身份模拟与匿名默认管理员。
- Unsplash 预设图片、1×1 占位图等 Demo 注入逻辑。
- 固定潮州范围、模拟河流、聚合点和假路线。
- 未执行成功就显示成功的前端分支。
- 当前公开且不安全的备份、恢复、删除和导出入口。

## 3. 阻塞问题

### P0：正式使用前必须解决

- 服务端构建为 CJS，但运行时依赖 `import.meta.url`，原 `npm start` 必然失败。
- 生产入口未可靠进入 production，可能加载 Vite 开发中间件。
- `x-user-id` 可冒充任意用户，匿名请求默认取得管理员身份。
- 管理员邀请码、备份、恢复、导出等敏感接口未完整保护。
- 默认弱密码和静态 SHA256 不可用于正式密码存储。
- `db.json` 整文件同步覆盖，解析异常时可能重建种子数据。
- PATCH 直接展开 `req.body`，存在批量赋值和越权字段修改。
- 恢复接口缺少文件名、路径和内容校验。
- 私有媒体仍通过静态 `/uploads` 公开访问。
- 上传不可靠校验真实格式、尺寸、像素和处理结果。

### P1：首个正式版本应解决

- `server.ts`、`App.tsx`、`TripPlanner.tsx`、`PlaceDetail.tsx` 体积过大。
- 前端存在串行全量加载和行程 N+1 请求。
- 收藏及地点状态不是用户维度。
- 行程日期、排序和删除缺少完整校验与事务。
- 高德地图、POI、逆地理编码和路线代理已接入；行程路线的持久化计算与移动端导航仍待完成。
- 三个上传入口行为不一致，EXIF 与缩略图未真正实现。
- 缺少统一错误、健康检查、自动化测试和回归基线。
- 前端主包超过 500 KB，需要按页面延迟加载。

## 4. 分阶段实施

### 阶段一：生产构建和本地正式启动（1–2 人日）

**目标**：形成可重复安装、检查、构建、启动和停止的本地生产运行方式。

**修改范围与文件**：

- `package.json`、锁文件：统一 npm，增加跨平台 clean、test 和生产冒烟脚本。
- `vite.config.ts`：客户端固定输出到 `dist/client`。
- `server.ts`、`src/server/config.ts`、`src/server/start.ts`：服务端 ESM 输出、环境配置、健康检查、错误边界和优雅退出。
- `.env.example`、`.gitignore`：明确本地配置与运行数据忽略规则。
- `tests/`、`scripts/`：最小健康测试和生产启动冒烟。

**技术方案**：客户端与服务端分别输出到 `dist/client`、`dist/server/index.mjs`；生产入口显式设置 production 且不加载 Vite；`GET /api/health` 返回环境和存储状态；无效端口在启动前失败。

**风险**：开发 Vite 中间件与生产静态文件挂载顺序变化；当前项目没有历史 Git 基线。

**验收**：全新安装后 lint、test、build、production smoke 全部通过；根页面和健康接口返回 200；生产包不依赖 Vite 运行；进程可以响应 SIGINT/SIGTERM。

### 阶段二：SQLite、迁移和旧数据导入（4–6 人日）

**目标**：用有外键、事务和版本迁移的 SQLite 替换 `db.json`。

**修改范围与文件**：`src/dbEngine.ts`、`src/types.ts`、服务端数据访问；新增 `src/server/db/`、`migrations/*.sql`、`scripts/import-json-to-sqlite.ts`。

**技术方案**：使用 `better-sqlite3`，启用 foreign keys、WAL、busy timeout；建立 `schema_migrations`；核心表覆盖用户、Session、邀请、地点、用户地点状态、访问、行程、行程日、项目、媒体、攻略和清单；旧数据单事务导入并保留 ID；旧密码和 SVG 占位媒体不迁移。

**风险**：全局收藏迁移到用户状态时需要归属规则；Demo 媒体不能当作正式文件；Schema 会影响后续权限和图片设计。

**验收**：空目录自动迁移；重复启动幂等；导入有统计和引用检查；外键与唯一约束生效；失败事务完整回滚；运行时不再读写 `db.json`。

### 阶段三：登录、Session 和权限（4–6 人日）

**目标**：建立不可伪造身份、服务端 Session 和私有成员制权限。

**修改范围与文件**：`src/api.ts`、`src/App.tsx`、服务端 auth/admin/业务路由；新增 `src/server/auth/`、`src/server/middleware/` 和权限测试。

**技术方案**：Argon2id 密码；随机 Session ID 存 SQLite；HttpOnly、SameSite=Lax Cookie；最长 30 天、连续 7 天续期；登录轮换、退出销毁；Origin 检查、登录限流、Zod 白名单输入。所有业务需登录；shared 成员可读，private 仅创建者/管理员；创建者/管理员可写；停用用户立即撤销 Session。

**风险**：前端需处理 401 和会话恢复；旧数据创建者归属可能不完整；Cookie 模型需避免 CSRF。

**验收**：未登录 401；普通用户无法访问管理接口或他人私有数据；`x-user-id` 无效；刷新保持登录、退出后旧 Session 失效；权限矩阵自动化测试通过。

### 阶段四：高德地图、POI 和路线（4–6 人日）

**目标**：保留地图页面布局，用真实高德能力替换模拟实现。

**修改范围与文件**：`MapContainer.tsx`、`TripPlanner.tsx`、手机端地图页面、`src/api.ts`；新增 `src/map/` 和服务端地图代理路由。

**技术方案**：使用 `@amap/amap-jsapi-loader`；POI、逆地理编码、路线通过登录保护的服务端接口；统一 WGS84/GCJ-02；内部 DTO 隔离高德原始响应；路线保存距离、预计时长、方式和计算时间；地点或方式变化后重新计算；手机端使用高德 URI 导航。

**风险**：Key 和安全密钥配置、坐标系偏移、配额限流、外部接口字段变化。

**验收**：PC/手机真实地图可缩放拖动；POI 搜索和地图选点可建地点；路线距离时间可计算；移动端可唤起导航；断网、无结果、超额有明确反馈；模拟地图代码移除。

### 阶段五：正式图片链路（4–6 人日）

**目标**：统一、安全地完成上传、校验、EXIF、派生图片和权限访问。

**修改范围与文件**：`src/api.ts`、`PhotosGallery.tsx`、`PlaceDetail.tsx`、手机端上传；新增 `src/server/media/` 和媒体表迁移。

**技术方案**：multipart；JPEG/PNG/WebP 和经本机验证的 HEIC；单文件 25 MB、解码后 60 MP；按文件签名和真实解码判型，拒绝 SVG/动画/损坏文件；Sharp 自动旋转，保留原图并生成最长边 2560 WebP 展示图和 480 WebP 缩略图；exifr 提取拍摄时间、设备、GPS；保存 WGS84 和 GCJ-02；临时写入后原子移动；内容哈希去重；媒体经受权 API 返回而非公开静态目录。

**风险**：HEIC 依赖本机 libvips 能力；大图内存峰值；EXIF 时区和 GPS 差异；文件与数据库一致性。

**验收**：三个入口行为一致；方向、缩略图、展示图正确；有无 EXIF 均可处理；非法或超限文件拒绝；私有媒体不可越权读取；失败不遗留正式孤儿文件。

### 阶段六：行程稳定、架构收敛和验收（3–5 人日）

**目标**：修复数据一致性问题，降低维护成本，形成完整回归保障。

**修改范围与文件**：`App.tsx`、`TripPlanner.tsx`、`PlaceDetail.tsx`、`server.ts`、`src/api.ts` 及拆分后的模块和测试。

**技术方案**：行程日期校验；日期调整、排序和删除使用事务；明确引用行为；服务端按 auth/places/trips/media/maps/admin 拆分；前端按会话、地点、行程、媒体拆分；聚合行程详情消除 N+1；照片游标分页；页面 lazy load；使用 Vitest、Supertest、Playwright 覆盖核心流程；清理 Demo 注入、假成功提示和未使用依赖。

**风险**：拆组件导致视觉或状态回归；行程日期变化时已有项目的安置；聚合接口改变加载时序。

**验收**：PC/手机视觉基线无明显回归；登录、地点、地图、图片、行程、退出可连续完成；失败写操作不留部分状态；核心权限、迁移、媒体和行程测试通过；本地生产运行 72 小时无数据损坏和未处理异常。

## 5. 主要接口与类型变化

- 身份仅来自 Session Cookie，删除 `x-user-id`。
- `POST /api/auth/login` 创建 Session，`POST /api/auth/logout` 销毁 Session，未登录 `GET /api/me` 返回 401。
- 错误统一为 `{ error: { code, message, details? } }`。
- 请求使用 Zod 白名单 Schema，禁止任意字段透传。
- `Place` 的收藏、想去、去过投影自 `UserPlaceState`。
- `Media` 增加原图/展示图/缩略图、哈希、尺寸、格式、EXIF 和处理状态。
- 地图接口使用项目内部 DTO，不向前端透传第三方原始响应。
- 行程详情增加聚合读取接口，写接口保持清晰资源边界。

## 6. 暂缓事项

部署完全由项目所有者处理，本计划不包含腾讯云、Docker、Nginx、域名、HTTPS、ICP备案、云端监控和发布流程。

正式备份与恢复暂缓。当前备份 UI 和匿名备份/恢复/删除接口应在正式使用前关闭，不再宣称 JSON 复制是完整备份。数据库迁移等高风险操作前可人工复制 SQLite 与媒体目录作为临时回滚；未来完整备份需同时覆盖 SQLite、媒体和清单并完成恢复演练，另估 3–5 人日。

## 8. 已确认默认决策

- 私有成员制；业务数据不允许匿名访问。
- shared 内容成员可读，private 仅创建者与管理员可读。
- 新内容默认 shared，允许用户改为 private。
- 有效旧数据尽量保留 ID；默认密码和占位媒体不迁移。
- 正式数据只保存于 SQLite 和受管理媒体目录。
- 不更换 React + TypeScript，不重新设计 UI。
- 部署与正式备份不在当前实施范围。
