# 手机定位与照片位置

## 运行前提

浏览器设备定位只在安全上下文中开放。电脑本机的 `localhost` 可作为例外，但手机访问
`http://电脑局域网 IP:3000` 不属于本机安全上下文，浏览器会拒绝设备定位。项目会保持当前地图视野并提示启用 HTTPS，不再使用网络出口 IP 猜测或移动地图。

正式部署推荐在应用前使用 Caddy 或 Nginx，并配置可信域名证书。仅在家庭局域网使用时：

1. 使用 `mkcert` 等工具生成包含实际访问域名或局域网 IP 的证书。
2. 将对应根证书安装到每台手机并设为信任。
3. 在 `.env` 设置：

```dotenv
APP_HOST=0.0.0.0
APP_TLS_CERT=local-tls/travel-footprint.pem
APP_TLS_KEY=local-tls/travel-footprint-key.pem
APP_ORIGIN=https://travel-footprint.home:3000
SESSION_COOKIE_SECURE=true
```

`local-tls/` 不得提交到 Git。修改环境变量后需要重启服务。

### 公网反向代理部署

如果由 Caddy、Nginx 或托管平台终止 HTTPS，Node 服务本身可以继续监听本机 HTTP，但必须设置浏览器实际访问的唯一来源：

```dotenv
NODE_ENV=production
APP_HOST=127.0.0.1
APP_PORT=3000
APP_ORIGIN=https://travel.example.com
SESSION_COOKIE_SECURE=true
SESSION_SECRET=至少32位的独立随机字符串
```

- `APP_ORIGIN` 必须与浏览器地址栏中的协议、域名和端口完全一致，末尾不要添加路径。
- `APP_TLS_CERT`、`APP_TLS_KEY` 只用于 Node 直接提供 HTTPS；由反向代理终止 HTTPS 时不要配置。
- `VITE_ALLOWED_HOSTS` 仅用于开发服务器，不影响 `npm run build` 后的生产静态文件。
- 高德 Key 按正式域名配置对应的安全域名白名单。

## 定位行为

- 地图定位会在最多 15 秒内连续采样，优先采用精度不超过 30 米的位置。
- 超时后只接受精度不差于 100 米的结果，并显示浏览器报告的误差范围。
- 首次打开地图不会自动请求定位；用户点击“定位”后才读取设备位置。
- 定位失败时保持当前地图视野，不使用 IP 定位，也不会生成或缓存伪位置。
- WGS-84 设备坐标只转换一次为 GCJ-02 后展示在高德地图。

## 照片位置来源

- 相册照片只使用文件自身的 EXIF/XMP 位置；不会自动套用“上传时当前位置”。
- “拍照上传”在文件没有 GPS 时可以请求浏览器当前位置，但只接受不差于 100 米的结果，
  且上传后仍要求在地图上确认或微调。
- 系统照片选择器、分享应用或隐私设置可能已经删除位置元数据。网页无法恢复被删除的数据，
  此时应手动选点、关联已有地点，或保留无位置照片。
- 服务端分别记录嵌入元数据、浏览器定位和手动选点来源；浏览器位置不会再伪装成 EXIF。

## 真机验收

1. 手机通过 HTTPS 打开应用，确认地址栏无证书警告。
2. 允许浏览器使用“精确位置”，点击手机地图分类栏的“定位”。
3. 确认界面显示 `±N 米`，并与系统地图对比。
4. 分别上传一张带 GPS 的原始照片、一张被脱敏照片，以及使用“拍照上传”新拍一张照片。
5. 验证带 GPS 照片进入地图确认态；脱敏照片进入手动选点；新拍照片只有在浏览器定位达到阈值时才预填位置。
